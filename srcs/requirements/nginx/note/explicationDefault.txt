listen 443 ssl; = sert a faire ecouter nginx en IPv4 sur le port 443
listen [::]:443 ssl; = sert a faire ecouter nginx en IPv6 sur le port 443
Il existe deux types d’adresses IP :
IPv4 → 127.0.0.1
IPv6 → ::1 (format abreger), sinon 2001:0db8:85a3:0000:0000:8a2e:0370:7334
:: = toutes les adresses IPv6
[] les crochets sont obligatoires quand on met un port
donc [::]:443 = toutes les adresses IPv6 sur le port 443
443 = port https
ssl = active TLS
ca marche meme si on met que le IPv4

location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass wordpress:9000;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        }
location ~ \.php$ = tte les url qui finissent par .php
include fastcgi_params; = charge un fichier de configuration nginx pour fastcgi
fastcgi = protocole qui permet a nginx de communiquer avec php-fpm (le moteur de php) car nginx ne comprend pas PHP
il sait seulement servir des fichiers statiques (html, images, css...)
donc quand il voit un .php, il doit demander a qq1 d'autre de l'executer donc ici c'est php-fpm
fastcgi_params contient des variables standard, par ex :
SCRIPT_FILENAME → le chemin du fichier PHP
QUERY_STRING → les paramètres de l’URL
REQUEST_METHOD → GET, POST, etc.
sans ca, php ne saurait pas quoi executer ni comment gerer la requete

fastcgi_pass wordpress:9000; = redirige la requete PHP vers le conteneur wordpress sur le port 9000
wordpress = nom du service docker dans ton docker-compose.yml
9000 = port par defaut ou php-fpm ecoute
docker permet aux conteneurs de communiquer via leur nom de service.
1. Le navigateur demande /index.php
2. NGINX reçoit la requête
3. Il voit .php
4. Il applique : fastcgi_pass wordpress:9000;
5. Il envoie la requête au conteneur WordPress
6. PHP-FPM exécute le script
7. Il renvoie du HTML
8. NGINX renvoie ce HTML au navigateur

fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name; = dit a php-fpm le chemin exact du fichier php qu'il doit executer
fastcgi_param = envoie une variable a fastcgi (donc a php-fpm)
SCRIPT_FILENAME = une variable standard que php comprend, elle contient le chemin complet du fichier php a executer
$document_root → /var/www/html (défini par root)
$fastcgi_script_name → le chemin demandé par la requête (ex : /index.php)
ex si l'utilisateur tape : https://tonlogin.42.fr/index.php
alors $fastcgi_script_name = /index.php


1. Navigateur → NGINX → requête /index.php
2. NGINX détecte .php → utilise cette location ~ \.php$
3. Inclut les paramètres FastCGI → prépare l’environnement PHP
4. Envoie la requête au conteneur WordPress : fastcgi_pass wordpress:9000
5. PHP-FPM exécute /var/www/html/index.php → retourne HTML
6. NGINX renvoie le HTML au navigateur
